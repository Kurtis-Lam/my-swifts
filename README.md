# Swift Playgrounds Apps

A collection of six small SwiftUI apps built as Swift Playgrounds app packages (`.swiftpm`). Each folder is a self-contained iOS app that can be opened and run on its own.

## Projects

| Folder | App | What it does |
| --- | --- | --- |
| `Your name counter.swiftpm` | Counter | A tap counter with `+`, `-` and `Reset` buttons and colored styling. |
| `My Game.swiftpm` | BMI Calculator | Takes weight (kg) and height (m), computes BMI and shows a category with an emoji. |
| `Drawing Cards.swiftpm` | Drawing Cards | Tap the Chance or Community deck image to draw a random board-game card, with a Reset button. |
| `Guess the Number Kurtis.swiftpm` | Guess the Number | Guess a hidden number from 1 to 100 and get too high, too low or correct feedback in an alert. |
| `Kurtis Quiz.swiftpm` | Quiz | A 10-question multiple-choice quiz with score tracking and a restart option. |
| `Wordle.swiftpm` | Wordle | Guess a random word and see how many letters are in the correct and wrong positions. |

## Requirements

- iOS or iPadOS 16.0 or later
- Swift Playgrounds 4.x on iPad or Mac, or Xcode 14.3 or later
- Swift tools version 5.7 (Your name counter, My Game) or 5.8 (all others)

## Running an App

1. Clone the repository.
2. Open any `.swiftpm` folder in Swift Playgrounds or Xcode.
3. Choose an iPhone or iPad simulator, or a connected device.
4. Press Run.

## Project Layout

Every package follows the same structure:

```
<Name>.swiftpm/
    Package.swift     app manifest (product name, icon, accent color, orientations)
    MyApp.swift       @main entry point presenting ContentView
    ContentView.swift all UI and game logic
```

`Drawing Cards.swiftpm` also contains `Assets.xcassets` with the `chance` and `community` card images.

## Notes

- `Package.swift` files are generated by Swift Playgrounds and should not be edited by hand.
- The `.swiftpm/` metadata folders (thumbnails, cached manifests, workspace settings) are excluded through `.gitignore`.

## Versioning

Commit messages end with `#major` for breaking changes, `#minor` for new features, or no tag for patch-level changes. Tooling can parse these tags to compute the next semantic version.
